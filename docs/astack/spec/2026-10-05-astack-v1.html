astack은 사용자의 에이전트가 사람이 이해하기 좋은 HTML을 만들게 하는 스킬 묶음이다. 개발은 하지 않고 이해만 맡는다.

목표는 하나다. 기다리는 순간마다 지금 일과 같은 맥락의 문서가 이미 준비돼 있게 한다.

그림의 색 = 관심사 · 실선 = 우리가 만드는 것 · 점선 = 바깥(계약으로만 만남) · 빨간 실 = 지금 보는 단계
3분 · 누가 무엇을 하나

사용자는 묻고 승인만 한다. 에이전트가 실제 일을 하고, astack 스킬이 "어떻게 이해시키나"를 알려준다.

bin/astack가 형식을 검사하고 한 줄을 남긴다. 파일이 진실이고, Rooms는 있으면 모아 보여준다.

이 문서는 P0~P1 구현 중에 썼다. bin/astack 흐름은 실제 코드를, 나머지(change, quest, dream)는 "스펙 기준"으로 보여준다.

§1

핵심 관심사와 아키텍처

1.1관심사 여섯 개: 누가 정하고, 누가 하나

astack이 만드는 것은 두 개뿐이다. 스킬(방법)과 bin/astack(검사와 기록)이다.

나머지 넷은 바깥이고, astack은 그들과 계약으로만 만난다. 그림의 색은 문서 전체에서 같은 관심사를 뜻한다.

에이전트는 일은 잘하지만 사람이 읽을 문서의 모양은 매번 다르게 만든다. 순서, 그림 규칙, 근거 등급을 한 곳에 적어 두어야 결과가 고르다.
없으면
지금처럼 Aside용과 Claude Code용 스킬이 갈라져 같은 스펙도 호스트마다 다른 문서가 된다 (§1.1).

없으면

범위

안에 두면
astack이 자기 런타임과 스케줄러를 갖게 된다. 맥미니 Hermes cron과 일이 겹친다.

왜 바깥에 두나
어떤 호스트든 파일은 쓸 수 있다. 사람이 열어 고치고 git으로 옮길 수 있다 (공리 5).
안에 두면
DB를 진실로 두면 호스트마다 그 DB에 붙는 코드가 필요하다.

안에 두면

안에 두면

그래서 Rooms를 지워도, 호스트를 바꿔도 이해물은 계속 생긴다.

1.2큰 그림: 에이전트가 쓰고, 스크립트가 확인하고, 파일이 남는다

사용자가 일을 시키면 에이전트가 일한다. 이해물을 만들 때는 astack 스킬을 읽고 HTML을 쓴다.

bin/astack가 그 HTML을 검사하고 파일에 한 줄을 남긴다. Rooms가 있으면 링크만 건다.

방향은 한쪽이다. 스킬 → HTML → 검사 → 기록. 거꾸로 들어오는 것은 사용자의 교정 한 줄뿐이다.

알림은 astack이 보내지 않는다. 시작한 곳의 호스트(Telegram이면 Hermes)가 보낸다 (§9.3).

1.5스킬 안의 구조: design 한 장이 모두의 규칙이다

design은 사용자가 직접 부르지 않는다. 다른 스킬이 시작할 때 먼저 읽는다.

출력 계약, 글쓰기, 시각화, 원칙 색인이 이 한 장에 있다 (§20.1 C5).

spec 같은 원자 스킬은 자기 구성과 체크리스트만 갖는다. 모양은 템플릿과 공유 키트가 정한다.

키트(alto.css, reader.js)는 확정 레퍼런스에서 그대로 뽑았고 손으로 고치지 않는다 (커밋 8fd01a8).

5.1무엇이 이해물인가

docs/astack/<스킬>/ 아래의 self-contained HTML 한 장이다. 여러 장이면 같은 이름 폴더에 둔다.

head 맨 앞에 메타 세 개, 본문에 30s · 3m · source 표식이 있어야 한다.

  1. 경로: <작업 위치>/docs/astack/<스킬>/YYYY-MM-DD-<slug>.html. 사용자 지시와 프로젝트 규칙이 우선이다.
  2. 메타: description(한두 줄), rooms:created(RFC3339), rooms:machine. 모두 앞 64KB 안.
  3. 세 층: 30초(무엇이고 왜 중요한지 두 줄), 3분(지도 하나), 그 아래 본문.
  4. 출처 줄: 원문 위치, 요청 원문, "Claude Code가 썼습니다".
  5. 메타 줄: 회색 한 줄, 세 항목까지. 링크·배지 없음.

5.2기억에 쓰는 것과 쓰지 않는 것

기록에서 다시 알 수 없는 것만 쓴다. 사용자가 말한 선호·제외·피드백·교정, 그리고 dream이 본 관심 변화다.

만든 것, 읽은 것, 구독, 좋아요는 쓰지 않는다. 파일과 로그에서 다시 만든다.

source뜻모순일 때
told사용자가 말함취소 전까지 유지. 최신 told가 이긴다
observed에이전트가 관찰오래되면 confidence가 줄어든다

type은 whitelist · exclude · correction · feedback · taste · preference 여섯 가지다. 그 밖은 add가 거부한다.

5.3주의력 등급과 예산

만드는 건 많이, 보여주는 건 적게. 업무(spec · change · recall now)가 언제나 먼저다.

자동 작업에는 스스로 멈출 지점이 없어 토큰 대신 개수로 상한을 둔다.

무거운 자동 작업은 밤에만 돈다. 실제 위험은 비용이 아니라 구독 사용량 한도다.

밤에 한도를 다 쓰면 낮 업무 에이전트가 멈춘다 (§9.6).

5.4자동으로 불리는 조건은 네 개뿐이다

접점성격Rooms가 없으면
HTML 메타: description + rooms:created, rooms:machine데이터무시되는 태그
rooms link <파일> [--room <이름>] [--journal <날짜>]명령 호출명령 없음 → 건너뜀
