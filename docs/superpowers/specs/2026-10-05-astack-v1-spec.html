astack v1

Spec · 2026-10-05 · Alto Computer · 대상 레포 alto-computer/astack · 상태: 초안
astack은 사용자의 에이전트가 Alto의 경험대로 "이해물"을 만들게 하는 선택형 빌트인 스킬이다. 설치하면 에이전트가 더 좋은 이해물을 만들고, 결국 사람이 더 잘 이해하게 된다.

0.개요

문제

  • 에이전트가 일하는 걸 멍하니 보는 시간이 늘었다. 예: superpowers subagent-driven-development로 Plan을 3시간 돌리면, 이해는 전부 끝난 뒤 한꺼번에 몰린다.
  • 궁금한 게 생겨도 바로 파고들 재고가 없다. 브리프에서 관심 항목을 찾아도 딥다이브를 요청하고 기다려야 해서 흐름이 끊긴다.
  • 이해물을 만드는 스킬이 흩어져 있다. Aside용과 Claude Code용 HTML 스킬이 서로 다른 규칙으로 갈라졌고, 맥미니와 다른 에이전트에서는 쓸 수 없다.

목표 (한 줄)

기다리는 모든 순간에, 지금 일과 같은 맥락의 이해물이 이미 준비돼 있다. 궁금한 건 던져두면 쌓이고, 쌓인 건 필요할 때 꺼내진다.

세 주체의 경계

주체하는 일하지 않는 일
사용자의 에이전트 (Claude Code, Codex, Hermes, Aside)실제로 일한다. 사용자 설정을 따른다
astack에이전트에게 잘 이해시키는 방법을 준다프로세스, 개발, 스케줄, 저장소 운영
Alto Rooms결과물을 모아서 보여준다AI 일
superpowers무엇을, 어떻게 만들지 (프로세스, 설계 관문)

astack과 Rooms는 서로를 몰라도 각각 동작한다. 하나만 설치한 사람도 잘 쓸 수 있어야 한다.

범위 밖

  • 개발 프로세스 스킬 (brainstorming, 계획, TDD, 리뷰). superpowers의 몫.
  • e2e 검증 문서. 증거는 PR 리뷰 게이트에서 본다.
  • 읽음 상태 추적. Rooms 클라이언트 상태라 astack은 알 수 없다.
  • 취미 브리프 (HF 논문 목록 등). 지금처럼 Instinct가 맡는다.
  • v1.1로 미룸: check (별도 점검 덱), article (긴 글, X 스레드), 월간 수렴.

용어

용어정의
이해물astack이 만드는 HTML 한 장. 사람이 읽고 이해하기 위한 것
교본quest, feed가 만드는 딥다이브 이해물
원자소스 하나 → 이해물 하나를 만드는 스킬. 이름은 소스 종류
재고쌓여 있는 이해물 전체. 할 일 목록이 아니라 서랍
작업 위치스킬이 실행되는 폴더. 결과물은 그 아래 docs/astack/에 쌓인다
호스트astack을 실행하는 에이전트. Claude Code, Codex, Hermes, Aside
능력"자막 가져오기"처럼 스킬이 필요로 하는 동작. 호스트마다 구현이 다르다

1.공리

모든 결정은 이 일곱 개에서 나온다. 개별 규칙과 충돌하면 공리가 이긴다.

1. 모든 산출물은 HTML이다.
퀴즈, 질의응답, 종합, 개념 설명 모두 HTML로 남긴다. 채팅과 알림에는 경로와 한 줄 요약만 둔다. 진행 상황, 실패 이유 같은 운영 메시지는 예외다. HTML은 파일 하나로 완결되고(self-contained), 저장소, API 키, 외부 호출 없이 격리 환경에서 동작해야 한다.
2. 이해만 한다.
"무엇을 할지"는 프로세스 도구(superpowers 등)가 만들고, "사람이 그걸 이해하게"는 astack이 만든다. 그래서 개발 문서(스펙, 변경)도 다루지만 개발 프로세스는 다루지 않는다.
3. 저장 위치는 환경을 따르고, Rooms가 있으면 링크한다.
기본 경로는 <작업 위치>/docs/astack/<스킬>/YYYY-MM-DD-<slug>.html이다. 사용자 지시와 프로젝트 규칙(CLAUDE.md, AGENTS.md)이 우선한다. rooms link 명령이 있으면 호출하고, 없으면 건너뛴다.
4. 런타임이 없다.
언제, 어디서 실행할지는 호스트가 정한다 (Hermes cron, 세션 훅). astack은 "어떻게 이해할지"만 안다. 대신 호스트용 설정 레시피를 함께 배포한다.
5. 상태는 파일에 있다.
astack의 상태는 ~/.astack/의 텍스트 파일뿐이다. 레포에는 틀만 있고 개인 데이터는 없다. 색인이 필요하면 파일에서 다시 만들 수 있는 파생물로만 둔다.
6. 이해는 비동기다. 재고는 넉넉히.
astack은 작업 흐름을 절대 멈추지 않는다. 기다리는 순간에 읽을 게 없으면 실패다. 설계를 확정하는 동기식 관문은 superpowers brainstorming의 HARD-GATE가 맡고, astack은 그 관문에서 빨리 깊게 이해하게 돕는다.
7. 만드는 건 많이, 보여주는 건 적게.
희소한 건 생산이 아니라 사람의 주의력이다. 재고는 할 일 목록이 아니라 서랍이다 (안 읽은 개수, 밀린 표시 없음). 업무 중 대기에는 같은 맥락만 내민다. 모든 이해물은 30초 / 3분 / 30분 세 층을 가진다. 고르는 비용을 줄이려고 "다음 하나"만 준다. 코스가 여러 장이어도 입구는 지도 한 장, 알림은 한 줄이다. 발산(quest, feed)만큼 수렴(dream, map)을 정해진 리듬으로 돌린다.
등급무엇다루는 방식
업무spec, change, recall now최우선. 대기 시간에만, 같은 맥락만
핵심 공부quest (실험 포함)적중률이 생명. 저녁에 내가 고른 것만 밤에 돌린다. map으로 수렴
아침 읽기feed (화이트리스트 채널)아침 30분 분량만 만든다
취미HF 논문 목록 등astack 밖 (Instinct)

2.사용자 시나리오

#상황일어나는 일
1Plan을 3시간 돌리는 중Task가 리뷰를 통과할 때마다 그 Task의 change가 백그라운드로 생긴다. 에이전트가 Task N+1을 만드는 동안 나는 Task N을 이해한다. 끝나면 Plan 전체 요약 한 장만 남는다
2개발 설계 중brainstorming이 스펙을 저장하면 spec이 이해용 HTML을 만든다 (지금도 동작 중). 결정 목록, 레거시 충돌, go 전 점검 퀴즈를 보고 승인한다
3대기 중 멍한 순간recall now → 지금 작업과 같은 맥락의 3분짜리 하나
4지하철에서 궁금한 게 생기면Telegram Quest 토픽에 한 줄 → 확인 없이 바로 진행 → 끝나면 즉시 알림. 교본이 재고에 쌓인다
5아침feed "오늘 30분" 한 장. 화이트리스트 채널 신작 중 30분 분량만, 읽는 순서대로. 밤 goal 결과도 같은 아침에 1통
6저녁dream이 하루를 엮고 간격 복습과 "내 말로 한 줄"을 묻는다. 21:00에 "오늘 밤 돌릴 질문"을 받는다. 고른 것만 밤에 goal로 돌린다
7집중 공부 시간study로 교본 하나를 깊게. 후속 질문과 더 파기가 같은 교본에 덧붙는다
8팟캐스트 보다가 직접/interview <링크> 또는 "이 인터뷰 정리해줘"
9실험이 궁금할 때"Aside vs browser-harness vs Chrome vs 새 헤드리스 브라우저 속도 비교" → 벤치를 찾거나 새로 만들어 밤에 돌린다 → 실험 보고서 + 재현 가능한 벤치 코드
10무언가를 공부하고 싶을 때"Codex CLI 공부" → 지도 + 10~12장 코스. 입구는 지도 한 장

3.스킬 카탈로그

3.1 사용자 동사

스킬하는 일입력 → 출력방식
quest만들어두기. 질문이면 소스부터 찾고, 실험이 필요하면 돌린다한 줄 질문 또는 소스 → 코스 (지도 + 장). 유형: 만들기 → 비교와 스타터 플랜, 개념 → 교본, 사례 → 케이스 스터디, 실험 → 실험 보고서와 벤치 코드비동기. 확인을 기다리지 않음. 낮에 던진 건 완료 시 즉시 무음 알림, 밤 goal은 아침에 묶어서. 기본 깊이 Standard
study깊게 이해하기교본 하나 + 후속 질문 → 같은 교본에 덧붙이거나 하위 교본 생성동기. 집중 공부 시간에만
recall재고에서 꺼내기. 새 이해를 만들지 않음주제 / 지금 작업 / 기간 → 읽을 목록 HTML. recall now는 딱 하나요청, 그리고 긴 작업 시작 시 자동

3.2 quest 상세

  1. 판별: 입력이 소스 하나면 해당 원자로 바로 간다. 질문이면 유형(만들기, 개념, 사례)을 정한다.
  2. 분해: 하위 질문 3~6개. 첫 알림에 보여주고, 답장이 오면 방향을 바꾼다. 기다리지 않는다.
  3. 수집과 선별: GitHub, 엔지니어링 블로그, 발표, 논문, X. 상위 3~5개를 고른다 (실사용, 최근 활동, 신뢰하는 사람의 언급).
  4. 원자 호출: 병렬 서브에이전트로 repo, seminar, interview, paper를 부른다.
  5. 종합: 하위 질문 × 소스 비교, 각자의 해법, 스타터 플랜 또는 교본, 점검 퀴즈.
  6. 적재와 알림: docs/astack/quest/<날짜>-<slug>/. 시작한 곳으로 알린다 (기본 Telegram).

3.2.1 결과물 단위: 코스

한 장에 다 넣으면 얕아지거나 안 읽힌다. 토큰이 넉넉하므로 quest의 결과는 코스 한 벌이다.

docs/astack/quest/<날짜>-<slug>/
  00-지도.html     입구. 전체 구조, 장별 30초 요약, 읽는 순서 (= 이 방의 map)
  01-….html ~ NN   장마다 질문 하나
규칙내용
한 장 = 한 질문장 제목이 질문 하나로 말해져야 한다
한 장 = 10~15분넘으면 쪼개고, 너무 짧으면 합친다
세 층 + 퀴즈장마다 30초 / 3분 / 본문, 끝에 점검
연결이전, 다음, 지도 링크. 같은 개념은 장이 달라도 같은 이름
깊이구성
Quick지도 + 5장
Standard (기본)지도 + 10~12장. why 장과 실험 또는 실습 장 포함
Deep지도 + 20장 이상. 장마다 하위 문서와 실습. "깊게"라고 할 때

만드는 순서: 장 설계(지도 초안) → 장마다 서브에이전트 병렬 집필(클론은 한 번 공유) → 용어 통일과 겹침 제거 → 지도 확정. 원자도 소스가 길면 같은 방식으로 장을 나눈다 (예: 3시간 팟캐스트).

3.2.2 실험 유형

  1. 가설과 지표: 무엇을 무엇으로 잴지 (페이지 로드, 스냅샷 시간, 액션 지연, 메모리 등).
  2. 기존 벤치 탐색: 쓸 만하면 재사용한다.
  3. 없으면 제작: 재현 가능한 스크립트. 벤치 자체가 남는 자산이다 (build-the-lever).
  4. 환경 고정: 머신, 버전, 워밍업, 교차 실행, 반복 횟수를 기록한다.
  5. 실행: 맥미니에서 밤에. 다른 작업과 자원을 다투지 않게.
  6. 분석: 숫자를 제한하는 요인과, 엉뚱한 걸 잰 건 아닌지까지 확인한다 (explain-the-number).
  7. 보고서: 방법, 차트, 원자료, 재현 명령, 한계. 벤치 코드는 quest 폴더에 보존한다.

브라우저 프로필: 기본은 Aside 실제 프로필 (로그인과 권한, 실사용 조건). 가드레일:

가드레일내용
읽기 전용로그인된 사이트에서는 읽고 이동만. 글쓰기, 구매, 삭제, 설정 변경 금지
세션 보존실제 프로필의 캐시, 쿠키를 지우지 않는다. 콜드 스타트 측정만 깨끗한 프로필
한 번에 하나Aside 프로필을 쓰는 goal은 순서대로. 병렬은 다른 브라우저끼리만
부하는 내 쪽에반복 측정은 로컬 테스트 페이지나 내 서버에서. 외부 사이트를 반복 호출해 계정이 제한되지 않게

비교 실험은 "실사용 조건"(Aside 프로필)과 "깨끗한 조건"(새 프로필)을 함께 잰다. 둘의 차이가 프로필 상태의 영향이다.

3.2.3 밤 goal

21:00에 Telegram으로 "오늘 밤 돌릴 질문"을 받는다. 후보는 오늘 작업에서 나온 질문, dream이 뽑은 새 질문, 요즘 관심사이고, 자유 입력도 받는다. 내가 고른 것만 돌려서 적중률을 높인다. 답이 없으면 후보 1번 하나만 돌린다.

항목설계
성공 조건유형별 판정. 예: 실험은 반복 3회와 편차 기준, 보고서와 재현 명령. 코스는 모든 장에 세 층과 퀴즈, 지도에서 모든 장 도달, 원문 근거
반복조건을 만족하거나 시간, 예산이 다 될 때까지
결정 기록밤새 무엇을 왜 정했는지 남긴다 (show-me-your-work 방식)
실패 대비체크포인트에서 이어간다 (pause/resume 방식)
개수밤에 최대 3개
아침07:00에 1통. goal별 성공 여부, 핵심 3줄, 지도 링크

클론 캐시: ~/.cache/astack/repos/. Rooms Home과 작업 위치 밖에 둬서 오염을 막고, 다음 quest에서 재사용한다.

3.3 원자

소스 하나 → 이해물 하나. 이름은 소스 종류다. quest의 부품이면서 직접 부를 수 있는 단축키다. 형식을 직접 정하고 싶을 때 쓴다.

스킬소스출력 형식자동 선택
interview팟캐스트, 인터뷰, 대담 영상대화를 보존한 매거진 에디션요청할 때만
seminar슬라이드 발표 영상스크롤하면 슬라이드가 바뀌는 리포트요청할 때만
paper논문 PDF, arXiv구조화, 시각화한 무손실 리더요청할 때만
repo외부 GitHub 레포아키텍처, 핵심 루프, 영리한 부분(파일:줄), why(PR, 이슈 근거), 약점요청할 때만

"정리해줘"처럼 요청하면 반응하고, 링크를 붙여넣기만 했을 땐 반응하지 않는다. 원자는 요약이 아니라 무손실 변환이며, 맨 위 3분 층이 요약 역할을 한다.

조건발동연결 방식

CLAUDE.md는 superpowers가 공식으로 열어둔 확장 지점이다 (사용자 지침이 스킬보다 우선). 지시가 무시되면 Claude Code 훅(서브에이전트 종료, PR 생성)으로 바꾼다.

## astack
- subagent-driven-development에서 Task가 리뷰를 통과할 때마다, 그 Task 커밋 범위로
  astack:change를 백그라운드 서브에이전트로 실행하고 경로를 한 줄로 알려줘. 작업은 멈추지 마.
- Plan이 끝나거나 PR을 열면 astack:change로 Plan 전체 요약을 만들어줘.
- 5분 넘게 걸릴 작업을 시작할 때 astack:recall now로 지금 읽을 것 하나를 알려줘.

4.3 알림

  • 시작한 곳으로 답한다. 보내는 쪽은 항상 호스트(Hermes 등)이고, astack은 일만 한다.
  • 준선 기본값: Telegram. 낮에 던진 quest는 완료 즉시 무음 메시지(도착하되 집중을 깨지 않음). 밤 goal과 feed는 아침 1통, dream은 저녁 1통, 21:00 질문 받기 1통.
  • quest 첫 응답("받았어요, 이렇게 쪼개서 볼게요")은 머릿속 열린 고리를 닫는 신호다. 던진 순간 잊어도 된다.
  • 메시지에는 30초 층(2~3줄)과 링크만. 본체는 HTML.

7.상태와 기억

파일역할
~/.astack/memory.jsonl기억의 진실. 한 줄에 기록 하나
~/.astack/archive/YYYY-MM-DD.jsonlconsolidate 직전 상태. 되돌리기와 감사용

~/.astack/.lockconsolidate 중에만 잡는 잠금
SQLitev1에는 없음. 필요해지면 jsonl에서 만드는 파생 색인

기록 형식

{"type":"exclude","key":"channel:남자의취미","insight":"feed에서 제외","source":"told","date":"2026-10-05","host":"hermes"}
{"type":"correction","key":"skill:interview","insight":"질문자 발언도 전부 살릴 것","source":"told","date":"2026-10-05","host":"claude"}
{"type":"taste","key":"topic:personal-agent","insight":"최근 2주 quest가 개인 에이전트 메모리로 몰림","confidence":0.7,"source":"observed","date":"2026-10-05","host":"hermes"}

누가, 언제 쓰나

  • 판단은 에이전트, 형식은 스크립트. 에이전트가 astack-memory add '{…}'를 호출하고, 스크립트가 형식을 검사하고 시간과 호스트를 붙인다. 짧은 한 줄 추가라 여러 에이전트가 동시에 써도 안전하다.
  • 기록에서 다시 알 수 없는 것만 쓴다. 사용자가 말한 선호, 제외, 피드백, 교정. 그리고 dream이 발견한 관심 변화. 무엇을 만들고 읽었는지, 구독과 좋아요는 쓰지 않는다 (재구성 가능).
  • 읽기: 스킬은 시작할 때 astack-memory search <관련 키>로 관련 기억을 읽는다.

consolidate (에이전트를 위한 dream)

  1. 잠금을 잡고 현재 파일을 archive로 복사한다.
  2. 중복을 합친다. 모순은 최신 told가 오래된 observed를 이긴다. 오래된 관찰은 약하게 만든다. told는 취소 전까지 유지한다.
  3. 반복된 교정을 승격한다. 내 취향(예: interview 교정 3회)은 기억 안의 강한 규칙으로 바꾼다. 스킬 결함(예: seminar 슬라이드 순서 오류 반복)은 astack 레포 패치를 제안만 한다.
  4. 임시 파일에 쓰고 이름을 바꿔 원자적으로 교체한다. 잠금을 푼다.
  5. 바뀐 게 있으면 변경 보고 HTML을 만든다.

취향 = 재구성 + 기억

astack은 구독 목록이나 취향 파일을 저장하지 않는다. 취향은 매번 기록(만든 이해물, 좋아요, 북마크, 구독)에서 재구성하고, 기록으로 알 수 없는 명시적 선호만 memory에서 읽는다.

예산 상한

자동 작업에는 스스로 멈출 지점이 없다. 실제 위험은 비용보다 구독 사용량 한도다. 밤사이 자동 작업이 한도를 써버리면 낮의 업무용 에이전트가 멈춘다. 토큰 계산 대신 개수로 제한한다.

자동 작업상한
feed아침 30분 분량
긴 작업 시작 시 선생성작업당 1개
밤 goal최대 3개 (Aside 프로필 사용 goal은 순서대로)
change (Task 단위)상한 없음. 업무 이해가 최우선
내가 시작한 quest, spec상한 없음

무거운 자동 작업은 밤에만 돌린다. 2주 운영 후 숫자를 조정한다. 우선순위: 지금 작업(spec, change, recall) > 내가 던진 quest와 밤 goal > feed.

10.Rooms 접점

astack과 Rooms의 접점은 두 개뿐이다. astack은 Rooms API(/v1/*)를 쓰지 않는다. dream, recall, 알림, 원격 보기는 전부 Rooms 없이 동작한다.

접점성격Rooms가 없으면
HTML 메타: 표준 description + rooms:created, rooms:machine데이터무시되는 태그
rooms link <파일> [--room <이름>] [--journal <날짜>]명령 호출명령이 없어 건너뜀

Alto Rooms 스펙에 추가할 것

  • <meta name="description">를 색인하고 카드에 한 줄 설명으로 보여준다 (스펙의 "한 줄 설명" 후속 이슈 해결).
  • /v1/search: FTS5로 제목, description, 본문을 검색한다. 사람이 Rooms 화면에서 쓰는 기능이며 astack은 쓰지 않는다.
  • rooms link CLI: 방 선택, 확신이 없으면 inbox, --journal 옵션. 링크 정책(원본이 있으면 링크)은 Rooms가 소유한다.
  • 멀티디바이스: 머신별 독립 Home. 통합은 v2 클라이언트 페더레이션.
  • roomsd는 launchd 상주, 앱 없이 단독 실행. 원격 리스너는 실행 플래그로 켠다.
  • 모르는 메타는 무시한다는 규칙을 명시한다.
원격 보기는 Rooms 전용이 아니다. Rooms 원격 보기, 맥미니 정적 서버 + Tailscale, Hermes의 Telegram 파일 첨부 중 무엇이든 된다. 파일을 띄우는 건 호스트의 일이고, astack은 어디서 열어도 같은 self-contained HTML까지만 책임진다.

12.마이그레이션

  1. 학습 추출: 기존 스킬에서 몇 달간 쌓인 경험을 원칙과 Gotchas로 옮긴다. 대상: Aside podcast-magazine, seminar-report, paper-lossless-reader, html-산출물-만들기, Claude Code html-artifact(+references). 예: AI-slop 카드 패턴, 자막 언어 명시, 섬네일 대체 프레임, Openverse 대체 이미지, 인터랙티브 흐름 가이드.
  2. 구현: 9장 순서와 무관하게 업무 이해(spec, change, recall)를 먼저 검증한다.
  3. 검증: 메인 맥 Claude Code와 Aside에 설치해 실제 소스로 한 번씩 돌린다.
  4. 삭제: 위 기존 스킬, results-dashboard.html, build-dashboard.js/.mjs. 프로젝트의 "결과물 대시보드 자동 갱신" 에이전트를 정리한다. 기존 HTML 54개는 지우지 않고 Rooms 온보딩으로 방에 링크한다.
  5. 메모리 정리: Aside 메모리에서 옛 스킬과 대시보드를 가리키는 내용을 고친다.
